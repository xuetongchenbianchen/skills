# 精度验证核对清单

## 通用前置清单（任何验证之前）

- [ ] 基线来源已确认（官方 / 用户 GPU / 仅调试）
- [ ] 已检查官方 README / 文档 / benchmark 是否给出基线
- [ ] 如做了 CPU 对比，已明确标注用途
- [ ] 确定性条件已设置（随机性关闭、JIT 禁用等）
- [ ] Baseline 环境已冻结（权重、配置、框架版本、精度模式）

## Level 1 快速验证清单（每次推理优化改动后）

### 分类与方案
- [ ] 已明确本次优化的预期验证路径：数值等价（预期 Step 1 通过）/ 近似算法（预期需要 Step 2）
- [ ] 首次接触该模型时，已推导验证方案（Φ、D、阈值）并保存为 validation_plan.yaml
- [ ] 非首次时，已确认复用之前冻结的验证方案

### 控制变量
- [ ] 输入完全一致：相同数据、相同前处理、相同条件参数
- [ ] 优化前后使用完全相同的随机种子（且确认 seed 配对有效）
- [ ] 优化前后使用完全相同的条件输入（prompt/label/reference）
- [ ] 后处理参数一致（scaling_factor、归一化反变换、temperature 等）

### 样本
- [ ] 样本覆盖代表性输入 + 边界 case + 困难样例
- [ ] 样本集已固定保存，每次 Level 1 使用相同样本

### 执行与判定
- [ ] 阈值已在比较前声明（不可看到结果后调整）
- [ ] 已计算指标并关注 worst case（不只看平均）
- [ ] Step 1（原始输出比较）：cosine + max_abs_diff 判定
- [ ] Step 1 不通过 + 声明数值等价 → 视为 bug，修复而非降级
- [ ] Step 1 不通过 + 声明近似算法 → 进入 Step 2，按 plan 的 Φ/D/阈值判定
- [ ] 结论未过度声称（Level 1 通过 ≠ "精度已保证"）

## Level 2 全量验证清单（版本提交前）

- [ ] 已从 model card / 论文确认评测数据集和指标
- [ ] 阈值预声明：在运行前定义允许退化量
- [ ] 已用 baseline 模型推理一遍，记录基线数值
- [ ] 评测数据集为标准公开集，使用完整 val/test set
- [ ] 评测指标计算方式与官方一致
- [ ] 前处理管道与模型发布时一致（tokenizer 版本、归一化参数等）
- [ ] 评测脚本可复现（固定 seed，记录所有超参和命令）
- [ ] 已与 Profiling 确认性能收益（两项门禁都通过才可提交）
- [ ] 输出结构化报告（含 baseline 实测值、optimized 实测值、退化量、判定结果）

## 训练精度对齐清单

- [ ] 两侧代码版本一致
- [ ] 使用同一 checkpoint 或初始化方式
- [ ] 数据集内容和顺序一致
- [ ] seed 和随机性控制一致
- [ ] batch size 与梯度累积一致
- [ ] 优化器、scheduler、warmup 一致
- [ ] loss 函数和 reduction 模式一致
- [ ] 精度模式与 autocast 边界一致
- [ ] 分布式 world size 和 reduction 语义一致

## 结论输出清单

- [ ] 明确说明验证层级（Level 1 / Level 2）
- [ ] 明确说明基线来源
- [ ] 明确说明比较覆盖范围（样本数量和覆盖维度）
- [ ] 明确说明使用的阈值及其依据
- [ ] 明确区分"已证实结论"和"合理推测"
- [ ] 如只覆盖示例级，未写成"模型已完成精度对齐"
- [ ] 如只做 CPU 对比，未写成正式对齐结论
- [ ] Level 1 通过未声称为"精度已保证"
