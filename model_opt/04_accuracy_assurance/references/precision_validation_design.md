# 精度验证方案设计指南

## 定位

本文档是 Level 1 快速验证中"确定验证方案"步骤的方法论。首次对某个模型执行 Level 1 时加载。方案确定后冻结复用，后续 Level 1 不需要再次加载本文档。

## 第一性原理

### 原理一：模型输出是手段，不是目的

模型的输出（logits、embedding、像素）本身不是用户要的东西。用户要的是输出被用来做的事——分类、检索、生成图像、识别语音。

因此，验证精度不是在问"输出的数字变没变"，而是在问"输出还能不能完成它该做的事"。

### 原理二：不是所有输出变化都影响任务

输出可以变化很大但任务完全不受影响，也可以变化极小但任务彻底失败：

- CTC logits 变了（cosine=0.984），但 argmax 序列不变 → 解码文本 100% 一致 → 任务无影响
- 分类 logits 只在第一名和第二名之间变了 0.01 → argmax 翻转 → 预测错误

关键区别在于：**变化发生在决策边界附近还是远离决策边界**。

### 原理三：输出空间的距离 ≠ 任务空间的距离

两个输出之间的"数值距离"（cosine、L2）和"任务影响"之间没有固定的映射关系。这个映射取决于：

1. 任务的决策函数对输出的哪个性质敏感
2. 变化发生在输出的哪个方向/区域

所以不存在一个"万能指标"能适用于所有模型。每个模型需要根据其任务的决策机制来选择验证指标。

### 原理四：好的验证指标需要"任务预测力"

一个指标有"任务预测力"意味着：知道这个指标的值，能预测任务表现有没有退化。

- 有预测力：NC@k = 1.0 → 数学保证 k-NN 预测不变
- 有预测力：CTC decode match = 100% → 必然 WER 不变
- 没有预测力：像素 cosine = 0.9（换 scheduler 时）→ 不能告诉你语义有没有变

指标的预测力来源于它和任务决策函数之间的因果关系或强统计相关。

### 原理五：确定性是一切比较的前提

如果 baseline 自己跑两次输出不同，那 baseline 和 optimized 之间的差异就无法归因于优化——可能只是随机波动。必须先确认可复现性，再做配对比较。

对于本质上是随机的模型（扩散、采样），需要换一种比较方式——比分布而不是比单点。

## 从原理推导出方法

### 推导出的核心问题

根据原理一和原理三，验证方案的设计归结为一个问题：

> **任务的决策函数对输出的什么性质敏感？**

回答了这个问题，就知道该测什么（Φ）、用什么尺子量（D）。

### 推导出的设计步骤

```
1. 理解任务的决策函数是什么
2. 识别决策函数对输出的哪个性质敏感
3. 选择 Φ：对单个样本的输出 Y_i，提取什么性质 → Φ(Y_i)
4. 选择 D：对单个样本，量化 Φ 变了多少 → d_i = D(Φ(Y_base_i), Φ(Y_opt_i))
5. 反例自检：能否构造 "d_i 通过阈值但任务失败" 的情况？能 → 回到步骤 3
6. 确定阈值 τ：单样本的 d_i 达到多少算有问题
7. 设计样本（覆盖决策函数的敏感区域）
```

### Φ 和 D 的作用域：单个样本

Φ 和 D 始终定义在**单个样本**上：

```
给定第 i 个样本的输入 x_i：
  Y_base_i = baseline(x_i)              # baseline 的输出
  Y_opt_i  = optimized(x_i)             # optimized 的输出
  φ_base_i = Φ(Y_base_i)               # 提取性质
  φ_opt_i  = Φ(Y_opt_i)                # 提取性质
  d_i      = D(φ_base_i, φ_opt_i)      # 单样本距离（标量）
```

选择 Φ 时的思考方式是：**对这一个样本的输出，什么性质决定了任务成败？**

例如：
- 分类模型：Φ(Y_i) = argmax(Y_i) — 这一个样本预测的类别
- 特征检索：Φ(Y_i) = normalize(Y_i) — 这一个样本的特征方向
- 文本生成：Φ(Y_i) = greedy_decode(Y_i) — 这一个 prompt 的生成序列
- 语音识别：Φ(Y_i) = CTC_decode(Y_i) — 这一段音频的转写文本

**不是**在问 "N 个样本的整体表现如何" — 那是汇聚后的事情。Φ/D 的设计只需要思考一个样本。

### 步骤 5：反例自检

选定 Φ 和 D 后，必须回答以下问题：

> **"能否构造一种情况，使得 d_i 通过阈值（Φ 说'没问题'），但该样本的任务实际上失败了？"**

#### 这是什么

反例自检是一个**逻辑推理过程**，不是跑实验。它问的是 Φ 的数学定义和 decision_function 之间有没有逻辑缝隙。

#### 怎么做（具体操作步骤）

```
1. 写出 Φ 衡量的性质 P_phi（从 phi.definition 得出）
2. 写出 decision_function 依赖的性质 P_task（从 task.sensitive_to 得出）
3. 问：P_phi 满足 ⟹ P_task 满足？（即 Φ 通过是否逻辑蕴含任务不变）
   - 是 → 因果性保证，不能构造反例
   - 否 → 存在缝隙，用缝隙构造反例
```

#### 具体示例（展示推理过程）

**示例 A：发现缝隙**

```
Φ = cosine(logits)
P_phi = "两个 logit 向量的方向相似度高"
P_task = "argmax 位置不变"（来自 decision_function: logits → argmax）

问：方向相似 ⟹ argmax 不变？
答：否。反例：[1.01, 1.00] 和 [1.00, 1.01] 方向几乎相同但 argmax 不同。
结论：Φ 有盲区，需要换。
```

**示例 B：没有缝隙（因果性）**

```
Φ = argmax(logits)
P_phi = "argmax 位置相同"
P_task = "argmax 位置不变"（来自 decision_function: logits → argmax）

问：argmax 位置相同 ⟹ argmax 不变？
答：是。这是同一个命题（恒等），逻辑上不可能 P_phi 成立而 P_task 不成立。
结论：因果性保证，无法构造反例。
```

**示例 C：有条件的因果性**

```
Φ = greedy_decode 序列完全一致
P_phi = "greedy 生成的 token 序列相同"
P_task = "输出文本相同"（来自 decision_function: logits → argmax → repeat → sequence）

问：greedy 序列相同 ⟹ 输出文本相同？
答：是 — 但仅在 do_sample=False 时成立。
    若 do_sample=True，greedy_decode 本身就不是 decision_function 的路径。
结论：有条件的因果性。条件（do_sample=False）必须写入验证方案。
```

**示例 D：缝隙存在但实测安全**

```
Φ = cosine(embedding)
P_phi = "embedding 方向偏移 < 0.8°"（cos > 0.9999）
P_task = "kNN 最近邻不变"（来自 decision_function: embedding → cosine_sim → top-k）

问：方向偏移小 ⟹ 最近邻不变？
答：否（理论上）。如果两个 gallery 点几乎等距，微小偏移可能翻转排序。
    但（实测上）在 768-dim 空间中 0.8° 偏移跨越 Voronoi 边界的概率极低。
    model_family_hints.md 记录 cos>0.9999 时 NC@20 实测不变。
结论：缝隙存在但被严格阈值封堵。标记为"经验性安全"，非"因果性保证"。
    预测力依赖阈值足够严格（0.9999 而非 0.999）。
```

#### 判定逻辑总结

| P_phi ⟹ P_task？ | 结论 | 行动 |
|-------------------|------|------|
| 是（恒等或逻辑蕴含） | 因果性保证 | Φ 可用，写出论证 |
| 否，且无法封堵 | Φ 有盲区 | 换 Φ 或加 secondary，重新自检 |
| 否，但严格阈值可封堵（有实测证据） | 经验性安全 | Φ 可用，标记为经验性，阈值必须严格 |
| 不确定 | 预测力未确认 | Φ 暂用，Level 1 结论降级为"异常检测" |

#### 不是什么

- **不是**用论文的 evaluation data 跑实验
- **不是**找真实样本证明 Φ 有效
- **是**逻辑推理：比较 "Φ 衡量的性质" 和 "task 依赖的性质" 是否等价
- 核心操作就是问一个蕴含关系：P_phi ⟹ P_task？

**反例自检的结果记录在 `validation_plan.yaml` 的 `phi.anti_example` 字段中。该字段为空 → 文件无效。**

### 推导出的指标选择逻辑

根据原理四，好的 Φ 应该满足：

- **因果性最强**：Φ 满足某个条件时，能数学保证任务不退化（如 NC@k=1 → k-NN 不变）
- **其次是强相关**：Φ 在某个范围内时，经验上任务不退化（如 cos > 0.999 → Top-1 不变，5 模型验证）
- **最弱是间接相关**：Φ 变化和任务退化有统计关联但不确定（如通用 cosine）

优先选因果性指标，其次选有校准证据的相关性指标。

## 信息获取

从以下来源获取模型和任务的信息（按可信度排序）：

1. 模型代码、配置、推理 API 和官方后处理逻辑
2. HuggingFace Model Card 或官方 README
3. 原论文（Abstract + Evaluation 章节 + 标准 benchmark）
4. 官方评测脚本（eval.py、benchmark 目录）
5. 同模型、同优化族的公开实验报告
6. 相似模型的经验（最低优先级，需注明不确定性）

需要弄清楚：
- 模型的输入和输出是什么
- 任务是什么，标准评测用什么指标
- 任务的决策函数怎么从输出得到最终结果（argmax？排序？语义匹配？解码？）

## 如何识别"决策函数对什么敏感"

### 思路：追踪从输出到最终结果的路径

```
模型输出 Y
    ↓ （什么操作？）
中间表示
    ↓ （什么操作？）
最终任务结果
```

路径上的每个操作决定了什么性质重要：

| 从输出到结果的操作 | 决策对什么敏感 | 不敏感的变化 |
|-------------------|--------------|-------------|
| argmax（取最大值位置） | top-1 的排序是否翻转 | 非 top 位置的数值变化 |
| k-NN（找最近邻） | 样本间的相对距离排序 | 所有向量统一平移/缩放 |
| softmax + 采样 | 高概率 token 的相对大小关系 | 低概率 token 的绝对值 |
| CTC/greedy decode | argmax 序列 | logits 绝对值（只要排序不变） |
| cosine matching | 向量方向 | 向量模长 |
| 阈值判断（>0.5?） | 值是否跨越阈值 | 远离阈值的值变化 |
| 人类感知（图像） | 语义内容、整体结构 | 单个像素的微小变化 |

### 思路：区分"鲁棒区域"和"敏感区域"

模型输出空间中有些区域对变化鲁棒（远离决策边界），有些区域敏感（决策边界附近）。

验证样本应该包含敏感区域的输入——这些才是最可能暴露问题的。例如：
- 分类模型中 top-1 和 top-2 置信度接近的样本
- 检索模型中邻居距离接近的样本
- 解码模型中 logits 差异小的位置

## 距离选择

根据 Φ 的数学结构选择 D：

| Φ 的性质 | 适用的距离 | 为什么 |
|---------|-----------|--------|
| 连续值，需要逐值比较 | atol/rtol、cosine、relative L2 | 直接衡量数值偏移 |
| 概率分布 | KL divergence | 衡量分布形状变化 |
| 离散决策（是/否） | agreement rate、翻转率 | 直接计数对错 |
| 排序关系 | NC@k、Rank correlation | 衡量的是关系而非绝对值 |
| 语义（无法直接量化） | cosine in 独立语义模型的 embedding space | 借助外部模型做桥梁 |
| 分布特征（无配对） | FID、KID | 衡量两组样本的分布距离 |

## 阈值确定

阈值回答的问题是："变化多大算有问题？"

根据原理二，阈值应该由"多大的 Φ 变化会开始影响任务"来决定，不是凭感觉选一个数。

**阈值来源（按可靠程度排序）**：

1. **因果性保证**：Φ 的某个条件数学保证任务不变（如 decode match = 100% → 阈值就是 100%）
2. **校准实验**：之前同时跑过数值和任务，观察到"Φ 在 X 范围内 → 任务不退化"
3. **精度分析推导**：从计算精度（fp16/fp32）和链路长度推导浮点误差预算
4. **Baseline 自身变异**：baseline 多次运行的差异就是"正常波动"的上界
5. **文献/社区经验**：如"INT8 量化 cosine 通常 > 0.99"
6. **无法确定时**：不捏造阈值，标记为"待 Level 2 确认"

**关键约束**：阈值必须在跑比较之前确定。不可以先看到结果，再找一个刚好能通过的阈值。

## 样本设计

样本的目标不是"越多越好"，而是"覆盖决策函数的敏感区域"。

**按输入空间的关键维度分层**：
- 代表性输入：真实负载中最常见的类型和长度
- 边界 case：最短/最长、极端数值、特殊格式
- 困难样例：历史出过问题的、接近决策边界的
- 多样性：不同形状、分布、语言/领域

**数量由覆盖度决定**：列出关键维度，每个维度取若干代表 → 总数通常 30-100。

**固定复用**：样本确定后版本化保存，每次 Level 1 复用同一批，确保不同改动之间结果可比。

## 校准映射

### 为什么需要校准

根据原理三，Φ 的数值和任务退化之间的映射关系不是先验已知的——它取决于具体模型。校准就是建立这个映射。

### 怎么做

同时跑 Φ（数值指标）和任务指标，观察对应关系：
1. 对同一模型的多种优化版本，分别记录 Φ 和任务指标
2. 观察"Φ 在什么范围内 → 任务不退化"
3. 将这个范围记为安全阈值

### 什么时候需要

- 首次接触一个模型
- 首次尝试新的优化类型
- 对 Φ 的预测力没有把握时

### 没有校准时

Level 1 只能做异常检测（"明显超出合理范围就是有问题"），不能声称"任务无退化"。最终判断交给 Level 2。

## 随机模型的处理

### 为什么需要特殊处理

根据原理五，确定性是配对比较的前提。随机模型的输出天然不同，不能逐点比较。

### seed 配对的条件

同 seed 只有在两套实现消费随机数的方式完全一致时才构成配对。如果优化改变了随机数消费顺序（如换了 sampler），即使 seed 相同输出也不配对。

### 替代方案

- **能配对时**：同 seed 逐样本比较（跟确定性模型一样）
- **不能配对时**：各自跑多 seed，比较输出的统计分布或语义特征分布
- **用 baseline 自变异做量尺**：如果 optimized vs baseline 的差异小于 baseline 自己换 seed 的差异，则变化在"正常随机波动"范围内

### 无法合理比较时

如果既不能配对也无法建立分布比较，返回"未解决"，不强行逐元素比较。
