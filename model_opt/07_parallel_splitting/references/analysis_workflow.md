# 分析指南

> 从"模型放不下"到"切分方案确认"的完整指南。结构：两节原理（怎么切、在哪里可切）→ 三步分析（每步先讲怎么想、再讲怎么做，估算由脚本完成）→ 通信实现的效率层次 → ★ 方案确认。
---
## 切分只做两件事

一切并行策略，不管叫什么名字，都在回答两个问题：

1. **在哪里切**——切在模型结构的哪一级：层/模块间（整层或整个模块搬到不同卡，通信只在分界处，频率低：PP 切层、EP 切专家模块）还是算子内（拆开单个算子的权重/激活，通信穿插在执行中，频率高：TP/SP）？DP 不切模型——复制完整模型、切数据。
2. **沿哪个维度切**——可切维还是归约维？切可切维零计算通信，切归约维必然引入集合通信。

> **核心直觉**：切**可切维**——各卡独立计算，零通信；输出沿该维分片，消费方需要完整张量时一次 AllGather **还原**（还原通信，非计算通信）。切**归约维**——各卡算出的是不完整的部分结果（求和/归一化/softmax 分母被切开），必须通信**完成聚合**。

| 在哪里切 | 沿什么维度切 | 通信 | 叫什么 |
|---------|------------|------|--------|
| 层/模块间（整层分卡） | 层间深度 | P2P | PP |
| 层/模块间（独立分支分卡） | 分支/专家 | AllToAll | EP |
| 不切模型（切数据） | batch（可切维） | 无 | DP |
| 算子内（拆权重矩阵） | 权重输出维（可切） | AllGather | TP 列并行 |
| 算子内（拆权重矩阵） | 权重输入维（归约） | AllReduce | TP 行并行 |
| 算子内（拆激活） | 归约维 | AG+RS | SP |
| 算子内（拆激活/状态） | 长归约轴 | 环形 P2P | CP |

遇到新架构不需要问"这是什么并行"。先判断算子在切分维上做不做聚合（→ 可切还是归约），再看算子类型（→ 通信原语），这两步就定下来了。

**「在哪里切」的权衡判据**：算子内切通信频率高（每层每步）、单次代价由集合通信决定；层/模块间切通信频率低但引入流水依赖。层数多、单层计算重时，算子内切（TP）的通信可被层间计算掩盖；层数少或单层计算轻时，高频集合通信反成瓶颈，优先层/模块间切或不切模型。

## 图拓扑约束切分位置

两动作回答"怎么切"，计算图拓扑回答"在哪里可切"——单算子的通信确定后，整体图结构进一步约束可行方案：

| 拓扑 | 特征 | 切分位置 |
|------|------|---------|
| 链式 | 层间串行依赖 | 深度维 → PP（代价：流水气泡） |
| 独立分支 | 多条互不依赖支路 | 各支路分卡 → EP 泛化 |
| 共享主干+分支 | 主干共享、分支按路由选择 | MoE 范式 → EP（需评估路由负载均衡，如 capacity_factor） |
| 重复块 | 同结构反复堆叠 | 块内 TP/SP、块间 PP |
| 长程归约 | 某算子沿极长轴归约 | 该轴 → CP（环形传递状态） |

新架构的分析顺序：先看图拓扑找可切位置 → 按「切分只做两件事」定切法 → 查第三步算子表定通信。Transformer 只是特例：attention/FFN 是线性算子（→TP），LayerNorm/softmax 是归约（→SP），MoE 是分支派发（→EP），长序列是长归约轴（→CP）。

## 第一步：什么在吃显存？

### 怎么想

显存里有两类东西，切法不同：
- **参数比例状态**：权重本身，不随输入变化。切它 = 切权重矩阵的输出/输入维（= TP）或按层分布（= PP）。
- **workload 比例状态**：随输入规模增长，分两种——**持久运行状态**（KV cache、SSM 隐藏状态、GNN 节点特征表等，跨前向步骤保留），切它 = 沿其增长维切（= CP）；**单样本激活**（前向中间值），切它 = 沿归约维切（= SP）。batch 维可切的激活主导场景切 batch 维即可（= 纯 DP），Phase 0 分诊已分流。

> 怎么判断持久状态：问"跨前向步骤有没有需要保留的东西？它沿什么维增长？"有且占主导 → 优先切增长维。

首要判据：切占主导的那一项。参数占主导 → 切权重维或按层分布（= TP/PP）；持久状态占主导 → 沿状态增长维切（= CP），或 TP/PP（切权重维/按层分布时持久状态同样被切，见估算脚本 memory 的并行度映射）；单样本激活占主导 → 沿归约维切（= SP）。

### 怎么做

读源码，提取：
1. **模型参数**：总参数量、参数显存、框架
2. **模块链路**：每模块输入/输出 shape、主导张量、计算类型、内存复杂度
3. **子模块拆解**：复杂模块列出子模块及通信 pattern

沿 forward 路径构建内存时间线：
1. 逐模块记录中间张量 shape 和生命周期（模块内释放 or 跨模块存活）
2. 计算每模块"同时存活张量总大小"的峰值（串行 N block 峰值 = 单 block 峰值 + 常驻）
3. **递归检查子模块**——隐藏的超线性消费者

## 第二步：切哪个维度？

### 怎么想

**优先序**：候选维度中选通信量最小的（第三步估算）；切分并行度取满足容量的最小值（通信量随并行度增长），剩余卡叠加切 batch 维（DP）扩吞吐。

**切归约维 → 要通信。切可切维 → 不通信。**

怎么判断？看算子在这个维度上做什么：
- 逐元素操作 → 任何维度都是可切维
- 求和/归一化/softmax 分母 → 沿聚合方向是归约维
- 矩阵乘 → 输入特征维是归约维（$Y_{ij} = \sum_k X_{ik} W_{kj}$，对 k 求和），输出维是可切维

增长阶决定收益：超线性（O(N²)）的维度切它收益最大；线性（O(N×d)）→ 切输入维度。

**切归约维激活（= SP）与切持久状态/长归约轴（= CP）的分工**：前者配 AG+RS / AllToAll；后者配环形 P2P——持久状态只有后者（及 TP/PP 的状态绑定）才真正被切分。

**非 2 的幂卡数**：优先将 2 的幂部分分配给切权重维度（HCCL 优化好），剩余分配给切数据维度；序列不整除时 padding 到可整除，计算后裁剪。

### 怎么做

定性分类，通过三个问题完成定位：

```
Q1: 显存超限的是什么？
├─ 权重占主导（参数比例状态）→ 切权重维度（= TP/PP）
├─ 持久状态/激活占主导（workload 比例状态）→ Q2
└─ 两者均超限 → 切权重 + Q2

Q2: 超限的 workload 比例状态是什么？
├─ 持久运行状态（跨前向保留）→ 沿状态增长维切（= CP）
├─ 激活超线性维（O(N²)+）→ 沿高阶维度切（= SP；极长归约轴 → CP）
└─ 激活线性维（O(N×d)）→ 沿输入维度切（= SP）

Q3（可叠加）：是否存在独立样本？（batch 维是可切维，切开零通信）
├─ 是 → 叠加切 batch 维（= DP）
└─ 否（单样本迭代）→ 仅模型并行
```

选定策略后建立**张量分布约定表**（即 evidence_db 的 `parallel_splitting.tensor_distribution_table` 字段），逐张量声明分布方式、每卡 shape、消费操作、恢复通信——须覆盖所有大张量及其配套张量（mask/index/position_ids 等，配套漏切是实测高频错误）。未声明张量视为潜在 bug。它是分析阶段的核心产出物——方案确认时展示、实施阶段逐模块对照实现、验证通过后随切分案例落库。

## 第三步：通信代价与可行性

### 怎么想

切分方案的成本是**三目标权衡**：单卡显存 $M$、通信代价 $T_{comm}$、计算效率 $\eta$（流水气泡与未重叠的通信拉低 $\eta$）。切分降低 $M$，但增大 $T_{comm}$、可能降低 $\eta$——三者不存在同时最优，方案比较是在显存约束下选通信/效率的帕累托点。本步在运行前完成估算：枚举候选配置 → 剪掉显存不可行与明显次优的 → 剩余少量候选供实测验证，避免"跑 → OOM → 换切法"的被动试错。

切了归约维，需要通信把部分结果合起来。补什么通信由算子类型决定，不用猜：

| 算子类型 | 切归约维后的通信 | 为什么 |
|---------|---------------|--------|
| 线性（切输入维=行并行） | AllReduce | 各卡算的是部分和，求和还原 |
| 线性（切输出维=列并行） | AllGather | 各卡算的是输出切片，拼接还原 |
| 归约（LayerNorm/softmax） | AG+RS | AG 还原完整输入，RS 分回分片 |
| 拼接（torch.cat/stack） | AllGather | 各卡持有分片，拼接还原完整张量 |
| 拆分（chunk/split） | ReduceScatter | 汇总后分发对应分片 |
| 跨界转置（分片维交换的 permute） | AllToAll | 行切 ↔ 列切的重分布 |
| 分支派发（MoE） | AllToAll | 把数据路由到对应分支 |
| 递归状态（RNN/SSM） | 环形 P2P | 状态在环上传递 |

通信算子类型由算子语义刚性确定，不能换。标准做法列并行+行并行配对，配对时仅一处 AllReduce。

### 怎么做

估算由脚本原地完成。模型与符号的详细说明见脚本注释，文档只规定接口与解读规则：

1. **填 spec.json**：从 [spec_template.json](../scripts/spec_template.json) 复制起步，字段定义（必填/默认/约束）见 [estimate_split.py](../scripts/estimate_split.py) 的 `load_spec` 说明——缺必填、非法值、未知字段均会被脚本报错拦下。核心输入是第一、二步的结论——状态尺寸（读源码提取）与 shape；硬件可省略（用典型值），候选可省略（用 `--cards N` 枚举）
2. **跑**：`python <skills>/model_opt/07_parallel_splitting/scripts/estimate_split.py --spec spec.json [--cards N]`
3. **读报告**：逐候选的显存分解 vs HBM×0.8、各切分动作的每卡发送量与 α-β 耗时、PP 气泡率、可行性与通信耗时排序；方案确认自查所需的 `actual_comm_bytes` / `lower_bound_comm_bytes` 直接取报告数值。**break-even 判断**（脚本给数据、判断在此）：候选间比较——切权重维并行度取多大、切权重维还是切归约维、切哪个维度；仅当单卡放得下时才有"切 vs 不切"的比较；某方案通信耗时高于其收益 → 回第二步换方案

> 报告数值是量级判断（整体误差 10-30%，动态 shape 按上界估）：用于候选间**相对比较**与剪枝，绝对耗时以回归 Phase 1 后的实测为准。跨维重分布（row↔col）依赖具体模型结构，脚本不覆盖，需要时在报告基础上手工追加；枚举不含 sp 维（SP 候选直接写进 candidates）。

### 等价性论证：代数等价 + 数值等价

**代数等价**（方案正确性）：按「切分只做两件事」逐张量推导——每个被切维度上的算子属于可切维（零通信）还是归约维（按上表配原语），切分 + 通信在代数上与单卡一致。张量分布约定表的"恢复通信"列即由此论证。

**数值等价**（隐性约束）：浮点加法不满足结合律，切分改变归约顺序——单卡顺序求和 vs 各卡先局部求和再聚合——不同切分方案、不同并行度 P 的浮点结果不同，典型差异 1e-5（BF16/FP16）~1e-7（FP32）量级。是否需要处理，取决于误差是否影响下游决策：

- 一般推理：差异在验证容差内（verify_split.py 分层 tolerance 已覆盖），方案确认时标注预期即可
- 评测打分 / RL 一致性 / 科学计算：边界敏感（评测分数可随切权重维并行度不同而漂移）——关键归约点用 FP32 归约（差异降至 1e-7 以下，代价 2× 归约通信量），或固定归约顺序（跨配置逐位一致，可能无法用最优算法）

## 通信实现的效率层次：先正确，再高效

通信实现的优先级分三层，不可混淆——混淆层级会引入正确性 bug 或性能回退：

1. **先对（正确性）**：切归约维后用什么通信算子由算子语义刚性决定，已在第三步等价性论证中确定，不能为了性能换算子。
2. **再选算法（效率）**：大消息用 Ring（带宽最优），小消息用 Tree（延迟最优），通信库（HCCL/NCCL）按消息大小自动选，不用手动配。理解判据用于诊断——小消息 KB 级时延迟项 α 主导，减少通信次数比减少通信量更有效。
3. **最后做重叠（隐藏）**：只有归约可结合（sum/max）的算子才能分块重叠。强递归依赖不能重叠，只能降频。

> **重叠不是免费的**：通信和计算共享 HBM 带宽，重叠时 GEMM 可能慢 1.8×；推理只有前向可重叠，窗口窄、收益有限——推理优先靠减少通信维度（减小切权重维并行度、把剩余卡留给数据副本）降低通信，而非依赖重叠。通算重叠属主流程 Phase 3 的掩盖维度（[hide_latency.md](../../03_optimization/references/hide_latency.md)），切分分析与实施阶段不做——估算也按未重叠的串行通信计。

## ★ 方案确认（分析完成 → 用户确认）

向用户展示并用 `ask_user_question` 确认：

- **切分方案**：张量分布约定表（逐张量声明分布方式、每卡 shape、消费操作、恢复通信）
- **定量估算**：切分后每卡峰值、通信代价、break-even 结论
- **数学等价性论证**：按第三步「等价性论证」逐张量推导（代数等价 + 数值敏感性判断 + 浮点误差预期标注）
- **风险应对**：known_pitfalls 及 mitigation

展示前自查：
- 切分后每卡峰值 < HBM × 0.8
- 每操作通信量 ratio = actual_comm_bytes / lower_bound_comm_bytes ≥ 1.0（< 1.0 = 估算有误；数值取估算报告输出，字段定义见 [schema](../../06_evidence_db/schema.md)）
- tensor_distribution_table 覆盖所有大张量**及其配套张量**（mask/index/position_ids 等——配套张量漏切是实测高频错误，未声明 = 潜在 bug）
- 每条 known_pitfall 有 mitigation

确认通过 → 进入实施（[implementation_guide.md](implementation_guide.md)）。evidence_db 记录在验证通过后统一进行（见 implementation_guide「记录与回归」）。
