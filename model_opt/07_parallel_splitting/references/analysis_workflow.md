# 分析指南

> 从"模型放不下"到"切分方案确认"的完整指南。每一步先讲怎么想，再讲怎么做。
>
> 分诊前置：OOM 根因分诊已在 [01_preparation/SKILL.md](../../01_preparation/SKILL.md)「多卡切分前置判定」完成。进入本文档即确认"本质需要并行"。实施与验证见 [implementation_guide.md](implementation_guide.md)。

## 切分只做两件事

一切并行策略，不管叫什么名字，都在回答两个问题：

1. **在哪里切**——算子边界切（整层搬走，PP/DP）还是算子内部切（拆开算子，TP/SP）？边界切通信少，内部切通信多。
2. **沿哪个维度切**——可切维还是归约维？切可切维零通信，切归约维必然引入集合通信。

> **核心直觉**：切一个维度会引入通信，当且仅当某个算子沿这个维做聚合（求和/归一化/softmax 分母）。聚合维 = 归约维，切它要通信；非聚合维 = 可切维，切它不通信。

| 在哪里切 | 沿什么维度切 | 通信 | 叫什么 |
|---------|------------|------|--------|
| 算子边界 | 层间深度 | P2P | PP |
| 算子边界 | batch（可切） | 无 | DP |
| 算子边界 | 分支（可切） | AllToAll | EP |
| 算子内部 | 权重输出维（可切） | AllGather | TP 列并行 |
| 算子内部 | 权重输入维（归约） | AllReduce | TP 行并行 |
| 算子内部 | 归约维 | AG+RS | SP |
| 算子内部 | 长归约轴 | 环形 P2P | CP |

遇到新架构不需要问"这是什么并行"。先判断算子在切分维上做不做聚合（→ 可切还是归约），再看算子类型（→ 通信原语），这两步就定下来了。

## 推理优先：减通信 > 做重叠 > 换算法

> 在开始分析前，先建立推理场景的核心视角：推理和训练的切分思路有本质区别。

- **DP 在推理时零通信**。训练要梯度 AllReduce，推理各卡独立跑不同样本。所以推理"能 DP 就不 TP"——DP 是白赚的扩吞吐。
- **重叠窗口只有训练的一半**。训练有前向+反向可重叠，推理只有前向，窗口窄。
- **通信直接进每步延迟**。训练通信影响吞吐，推理通信直接拉高每个 token 的延迟。

所以推理优先级：减通信 > 做重叠 > 换算法。能靠 DP 扩吞吐就别上 TP；上了 TP 就尽量减小 TP size。

## 第一步：什么在吃显存？

### 怎么想

显存里有两类东西，切法不同：
- **参数比例状态**：权重本身，不随输入变化。切它 = TP/PP。
- **workload 比例状态**：激活值 + 推理特有的持久运行状态（KV cache、SSM 隐藏状态等），随输入规模增长。切它 = SP/CP。

> 怎么判断持久状态：问"跨前向步骤有没有需要保留的东西？它沿什么维增长？"有且占主导 → 优先切增长维。

首要判据：切占主导的那一项。参数占主导 → TP/PP；持久状态占主导 → CP/SP；无持久状态 → 通常 DP 就够了。

### 怎么做

读源码，提取：
1. **模型参数**：总参数量、参数显存、框架
2. **模块链路**：每模块输入/输出 shape、主导张量、计算类型、内存复杂度
3. **子模块拆解**：复杂模块列出子模块及通信 pattern

沿 forward 路径构建内存时间线：
1. 逐模块记录中间张量 shape 和生命周期（模块内释放 or 跨模块存活）
2. 计算每模块"同时存活张量总大小"的峰值（串行 N block 峰值 = 单 block 峰值 + 常驻）
3. **递归检查子模块**——隐藏的超线性消费者

## 第二步：切哪个维度？

### 怎么想

**切归约维 → 要通信。切可切维 → 不通信。**

怎么判断？看算子在这个维度上做什么：
- 逐元素操作 → 任何维度都是可切维
- 求和/归一化/softmax 分母 → 沿聚合方向是归约维
- 矩阵乘 → 输入特征维是归约维（$Y_{ij} = \sum_k X_{ik} W_{kj}$，对 k 求和），输出维是可切维

增长阶决定收益：超线性（O(N²)）的维度切它收益最大；线性（O(N×d)）→ 切输入维度。

### 怎么做

定性分类，通过三个问题完成定位：

```
Q1: 显存超限的是什么？
├─ 权重占主导（参数比例状态）→ 切权重维度（= TP/PP）
├─ 激活/持久状态占主导（workload 比例状态）→ Q2
└─ 两者均超限 → 切权重 + Q2

Q2: 超限的 workload 比例状态张量沿什么维度增长？
├─ 超线性（O(N²) 及以上）→ 沿高阶维度切（= SP），收益最大
└─ 线性（O(N×d)）→ 沿输入维度切（= SP）

Q3（可叠加）：是否存在独立样本？（batch 维是可切维，切开零通信）
├─ 是 → 叠加切 batch 维（= DP）
└─ 否（单样本迭代）→ 仅模型并行
```

选定策略后建立**张量分布约定表**，逐张量声明分布方式、每卡 shape、消费操作、恢复通信。未声明张量视为潜在 bug。

## 第三步：通信代价与可行性

### 怎么想

切了归约维，需要通信把部分结果合起来。补什么通信由算子类型决定，不用猜：

| 算子类型 | 切归约维后的通信 | 为什么 |
|---------|---------------|--------|
| 线性（切输入维=行并行） | AllReduce | 各卡算的是部分和，求和还原 |
| 线性（切输出维=列并行） | AllGather | 各卡算的是输出切片，拼接还原 |
| 归约（LayerNorm/softmax） | AG+RS | AG 还原完整输入，RS 分回分片 |
| 分支派发（MoE） | AllToAll | 把数据路由到对应分支 |
| 递归状态（RNN/SSM） | 环形 P2P | 状态在环上传递 |

通信算子类型由算子语义刚性确定，不能换。标准做法列并行+行并行配对，配对时仅一处 AllReduce。

### 怎么做

Agent 直接计算（P = 切分数；单维度切分时 P = world_size，混合切分时各维度各有自己的 P）：

1. **切分后每卡峰值**：$M = \frac{M_{param}}{p_{param}} + \frac{M_{state}}{p_{state}} + \frac{M_{act}}{p_{act}} + M_{overhead}$，需 < HBM × 0.8
2. **通信量**（推理频率均为仅前向，无反向阶段）：

   | 切分动作 | 通信量/步 | 推理频率 | 通信代价公式 |
   |---------|---------|---------|-------------|
   | 切 batch 维（DP） | — | 0（零通信） | 无 |
   | 切权重维（TP） | (P-1)/P × tensor_size | 每层 1× | L × T_AR(bsh, P) |
   | 切归约维（SP） | (P-1)/P × tensor_size | 每层 1× | L × (T_AG + T_RS) |
   | 切 seq/空间维 | (P-1)/P × tensor_size | 每次切分 1× | 切分次数 × T_A2A |
   | 切层维（PP） | b × s × h | 每 stage 边界 1× | P × T_p2p(bsh)；气泡率 = (P-1)/(P+m-1)，推理 m=1 时极高 |
   | 切分支维（EP） | token × h | 每 MoE 层 1× | L_moe × T_A2A |
   | 切长归约轴（CP） | s × h / P | 环形 P 步 | P × T_p2p(sh/P) |

3. **通信耗时** = total_comm / bandwidth
4. **break-even**：通信耗时 > 切分收益 → 不值得，回第二步换方案

> L 为层数，b 为 batch，s 为序列长，h 为 hidden dim。推理通信频率约为训练的一半（无反向），但通信占计算比例反而更高——这是推理对 TP size 敏感的根本原因。DP 在推理时零通信，是"能 DP 就不 TP"的依据。

## 切分维度速查

各策略的操作要点（思考框架见上方各步，实施脚本见 [implementation_guide.md](implementation_guide.md)）：

- **DP**（切 batch 维）：可切维，各卡独立零通信。简单 batch 切分不进入本子技能。
- **SP**（切 seq/空间维）：通信取决于算子——归约算子→AG+RS，跨卡重分布→AllToAll。原语：`local_chunk`、`allgather_along_dim`、`row_to_col`/`col_to_row`（自动 `.contiguous()`），`world_size=1` 时 no-op。
- **TP**（切权重矩阵）：切输出维→AllGather 拼接切片，切输入维→AllReduce 求和部分和，标准配对仅一处 AllReduce。通信量 = (P-1)/P × tensor_size × 层数。
- **PP**（切层）：P2P 传递段间依赖。气泡率 = (P-1)/(P+m-1)，推理 m=1 时极高，通常不推荐。
- **EP**（MoE 专家维）：AllToAll 分发到对应专家。需评估 capacity_factor 和负载均衡。
- **CP**（长序列归约）：环形 P2P 传递状态。适用序列远超单卡显存的长上下文场景。

**非 2 的幂卡数**：优先将 2 的幂部分分配给切权重维度（HCCL 优化好），剩余分配给切数据维度。序列不整除时 padding 到可整除，计算后裁剪。

## 通信设计：先对 → 再选算法 → 最后做重叠

通信怎么实现？按三层来，不能跳：

1. **先对**：切归约维后，用什么通信算子由算子语义刚性决定（见第三步表）。这层不能出错。
2. **再选算法**：大消息用 Ring（带宽最优），小消息用 Tree（延迟最优）。通信库（HCCL/NCCL）自动选，不用手动配。理解原理是为了诊断。
3. **最后做重叠**：只有归约可结合（sum/max）的算子才能分块重叠。强递归依赖不能重叠，只能降频。

> **重叠不是免费的**：通信和计算共享 HBM 带宽，重叠时 GEMM 可能慢 1.8×。推理重叠窗口窄，收益更有限——这是推理优先减通信而非依赖重叠的又一依据。

## 第四步：记录分析 → ★ 确认

将前三步的分析结果（模型张量图、切分方案、定量估算、等价性证明、已知坑）记录到 evidence_db。Schema 见 [06_evidence_db/schema.md](../../06_evidence_db/schema.md) 的 `optimization.attempts[].parallel_splitting` 字段。

记录时确保：
- 切分后每卡峰值 < HBM × 0.8
- 每操作通信 ratio ≥ 1.0（< 1.0 = 估算有误）
- tensor_distribution_table 覆盖所有大张量
- 每条 known_pitfall 有 mitigation

全过 → ★ 确认节点（展示切分方案 + 定量估算 + 等价性证明 + 风险应对）。未过 → 回第三步。
