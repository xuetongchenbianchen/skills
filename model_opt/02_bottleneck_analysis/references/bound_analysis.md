# 下界分析：还有没有优化空间、还有多少

> Phase 2 开局用它估算两侧剩余空间并路由本轮分析重心；★C 用它给出终局建议。只回答"还有多少"，不回答"空间在哪、怎么缩小"——那是双线分析与合并的职责。

## 分解模型

```
wall-clock ≈ L0 Computing + L0 Free
```

- **L0 Computing**：kernel 执行时间之和（不含 kernel 间 gap）
- **L0 Free**：device 空闲时间（kernel 间 gap 总和）

口径校准（实测验证）：L0 Computing = sum of kernel durations（差值为 0）；L0 Total / wall-clock = 1.00–1.03（profiler 开销 0–3%）。

**假设与失效条件**：分解依赖单流串行执行。多流重叠生效后（掩盖类优化），kernel 时间之和可能超过 wall-clock——此时 Computing 之和不再是时间线长度，分解退化为关键路径视角（Free 仍测 device 空闲，但两侧数字须按重叠度解读）。

## 两侧对称：都可压缩，也都有下界

| 侧 | 可压缩来源 | 下界 |
|----|-----------|------|
| **Free**（device 空闲） | 减少 dispatch 次数（去重/融合）、编译工具、通信-计算重叠 | 不可避免的 launch 开销与依赖等待 |
| **Computing**（kernel 执行） | 去重消除冗余 kernel、融合减少中间结果读写、等价替换更优 kernel/dtype、算法替换降低复杂度、（量化——需用户同意） | 必要计算量在当前算法与精度下的最小执行时间 |

**任一侧到界只是瓶颈转移信号，不是终局**：Free 耗尽 → 瓶颈在 device 侧，后续轮次转向 Computing 压缩；Computing 到下界而 Free 仍大 → host 侧仍有空间。

## 空间路由（每轮 Phase 2 开局）

读取上一轮 L0 的 Computing/Free 占比：

- **Free 占比高** → 本轮重心 host 侧/掩盖（dispatch、编译、重叠）
- **Free 占比低**（<10%，负载相关默认值）→ 本轮重心 device 侧（Computing 压缩链：去重 → 融合 → 替换 → 算法 → 量化）

路由决定分析重心，**不是停止条件**。

## 下界的经验逼近

两侧下界都难以先验计算（哪些 kernel 必要、融合能省多少取决于模型结构与实测），用**跨轮趋势**逼近：

- **Computing 趋势**：每轮优化后持续下降（去重/融合生效）→ 仍有压缩空间；连续 2 轮不降 → 当前算法与精度下的 kernel 时间接近下界
- **Free 趋势**：持续下降 → host 侧仍在产出；Free 仍存在但连续 2 轮消除不再带来 wall-clock 改善 → host 侧接近下界

## 终局判断（建议停止的条件）

以下条件**同时满足**时，才向用户建议停止：

1. **端到端停滞**：连续 2 轮 wall-clock 改善 < 2%（负载相关默认值）——聚合真值信号，无论空间在哪个侧；停滞原因用上节双侧趋势诊断说明（哪侧到了下界）
2. **候选穷尽**：无新候选产生且现有候选全部被排除——终局判断前必须穷尽 NPU 融合算子库，不能仅看 utilization 数字下结论
3. **用户决策项已摆出**：把需要用户授权的剩余手段（量化等精度换速度选项）在 ★C 中明确列出，由用户选择——不得默认停止而隐瞒该选项

## 可选：循环场景分解

当推理路径包含显式循环（for/while）时，可进一步分解：

```
wall-clock = one_time_cost + loop_cost
loop_cost = loop_device + loop_free
```

优化空间仍覆盖两侧。分解的价值在于让 agent 看到"每步的空闲时间有多少"——但具体是循环间间隙还是循环内间隙，属于双线分析。

**串行依赖场景**（每步依赖前一步输出）：loop_cost = N_steps × per_step_total。当前下界基于串行假设。

**并行场景**（各步独立无数据依赖）：若源码分析发现步骤可并行，下界应标注"当前下界基于串行假设，若可并行则下界更低"。但并行实现属于"掩盖"维度优化，不在下界分析范围。
